Rejoindre la salle FARCI

Le code se clone avec git ; les fichiers volumineux (modèles, images) se téléchargent à part. Comptez 10 minutes pour les étapes 1 à 5.

1Cloner le projet

Cloner, c'est recevoir le projet et tout son historique (Mac, Linux, Windows avec WSL) :

git clone http://HOTE/farci.git farci

Copie servie par la machine du formateur, en lecture seule.

Sans git : farci.tar.gz ou farci.zip, à décompresser — mais sans historique ni branche. …

2Pointer vers la salle

cd farci && curl -o config/network.env http://HOTE/partage/network.env

Ce fichier contient seulement l'adresse de la salle et les ports : vous n'avez rien à modifier.

3Installer les dépendances Python

FARCI_WHEELS_URL=http://HOTE/partage/wheels/ ./bin/farci bootstrap

Mac (Intel ou Apple Silicon), Linux ou Windows avec WSL ; Python 3.11 à 3.13. …

4Vérifier

./bin/farci doctor

Attendu : « accueil de la salle : joignable ». Le tableau de la salle : /tableau.

5Votre branche

Une branche est votre version du projet, adaptée à cette machine et à votre rôle. Remplacez N par votre équipe et SURNOM par le surnom de la machine (pas le vôtre) :

git switch -c poste/equipe-N-SURNOM
./bin/farci poste nouveau

La commande écrit la fiche de votre poste (mémoire, carte graphique, fonction dans le projet). Ensuite, ./bin/farci poste vous donne à chaque fois la commande git suivante : commit, push, Pull Request. Le guide : ./bin/farci docs git.

6Votre brique : les images Docker

Seulement si votre équipe héberge une brique (étape 1). Téléchargez l'image de votre brique (votre fiche d'équipe dit laquelle), puis chargez-la :

PC Intel / AMD …
images x86
Mac Apple Silicon …
images arm64
curl -O http://HOTE/partage/offline-x86/images/NOM.tar && docker load -i NOM.tar

Le Wi-Fi de la salle est partagé : une image lourde prend plusieurs minutes.

★Pas de machine utilisable ?

Vous participez quand même : en binôme pour l'étape 1, et pour l'étape 2 avec l'interface de discussion de la salle, dans un navigateur : Open WebUI.
